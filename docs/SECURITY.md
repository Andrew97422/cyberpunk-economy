# Безопасность

## Управление секретами

- **Никаких реальных секретов в git.** Реальные значения живут только в `.env` на машине
  (файл в `.gitignore`). В репозитории — только шаблоны: `.env.example` (одиночный хост) и
  `.env.multi.example` (мульти-машинный).
- **Compose fail-closed.** Секретные переменные объявлены как обязательные
  (`${APP_JWT_SECRET:?...}`, `${DB_PASSWORD:?...}`, `${BOOTSTRAP_ADMIN_PASSWORD:?...}`) —
  `docker compose up` падает с понятной ошибкой, если значение не задано. Слабых дефолтов в
  деплое больше нет.
- **Генерация секретов:**
  ```bash
  openssl rand -base64 48   # APP_JWT_SECRET (валидный Base64)
  openssl rand -hex 24      # DB_PASSWORD
  openssl rand -hex 12      # BOOTSTRAP_ADMIN_PASSWORD
  ```

## Процедура при утечке секрета

1. Сгенерировать новые значения (команды выше), обновить `.env` на всех машинах.
2. Перезапустить стек (`docker compose up -d`).
3. Старые JWT инвалидируются сменой `APP_JWT_SECRET`; сменить пароль администратора в UI.
4. При утечке в git — вычистить историю (filter-repo/BFG) и форс-пуш, либо пересоздать репозиторий.
