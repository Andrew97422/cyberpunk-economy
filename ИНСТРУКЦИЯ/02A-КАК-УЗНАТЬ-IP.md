# 🔢 02A — Как работают IP-адреса и как их узнать

Этот файл — азы для тех, кто «слабо в теме». Без него легко вписать неправильный
адрес и потом час искать, почему «ничего не работает». Читай перед
[02 — Сеть и роутеры](02-СЕТЬ-И-РОУТЕРЫ.md).

> ⚠️ Во всех инструкциях адреса вида `192.168.1.x` — это **ПРИМЕР**. Твоя реальная
> подсеть может быть другой (напр. `192.168.10.x`). Сначала узнай её (раздел 2),
> потом подставляй свои числа везде.

---

## 1. Что такое IP, подсеть и шлюз (на пальцах)

- **IP-адрес** — «номер квартиры» устройства в сети, напр. `192.168.1.10`.
- **Подсеть** — «дом». Обычно первые три числа общие у всех: `192.168.1.X`.
  Все устройства с одинаковыми первыми тремя числами видят друг друга напрямую.
- **Шлюз (Default Gateway)** — это и есть **главный роутер**, напр. `192.168.1.1`.
- **DHCP** — служба роутера, которая раздаёт IP автоматически (телефонам игроков и т.д.).
- **DHCP reservation (привязка)** — «забронировать» конкретный IP за конкретным
  устройством, чтобы он не менялся. Нужно для ноута A.

Главное правило: **все устройства (оба ноута, оба роутера, телефоны) — в одной
подсети** (одинаковые первые три числа).

---

## 2. Какую подсеть использует главный роутер (Cudy)?

Самый простой способ — подключить любое устройство к Wi-Fi роутера и посмотреть шлюз.

**На ноуте (PowerShell), когда он подключён к Cudy:**
```powershell
Get-NetIPConfiguration | Where-Object { $_.IPv4DefaultGateway } |
  Select-Object InterfaceAlias,
    @{n='Твой_IP';e={$_.IPv4Address.IPAddress}},
    @{n='Роутер_шлюз';e={$_.IPv4DefaultGateway.NextHop}}
```

Пример вывода:
```
InterfaceAlias  Твой_IP        Роутер_шлюз
--------------  -------        -----------
Wi-Fi           192.168.1.105  192.168.1.1
```
Значит: подсеть — `192.168.1.X`, главный роутер — `192.168.1.1`. Если бы шлюз был
`192.168.10.1` — подсеть была бы `192.168.10.X`, и все адреса в инструкции надо
читать как `192.168.10.*`.

> Эта команда показывает только адаптер с выходом в сеть (со шлюзом) и сразу
> отсекает виртуальные Docker/WSL-адаптеры. Это и есть твой настоящий сетевой адрес.

---

## 3. Как узнать IP именно НОУТА A (а не Docker/WSL)

На ноуте с Docker `ipconfig` покажет кучу адаптеров. Нужен тот, у которого есть
**Default Gateway** (роутер) — это твой реальный LAN-адрес. Та же команда:
```powershell
Get-NetIPConfiguration | Where-Object { $_.IPv4DefaultGateway } |
  Select-Object InterfaceAlias,
    @{n='IP';e={$_.IPv4Address.IPAddress}},
    @{n='MAC';e={(Get-NetAdapter -InterfaceIndex $_.InterfaceIndex).MacAddress}}
```
- **IP** отсюда — это адрес, который пишем в `-CoreHost` и в `CORE_HOST` (`.env`).
- **MAC** отсюда — его привязываем на роутере (DHCP reservation).
- **InterfaceAlias** (`Wi-Fi` или `Ethernet`) — через что ноут подключён.

> ❌ Игнорируй адаптеры `vEthernet (WSL)`, `vEthernet (Default Switch)`,
> `Docker*` и адреса `172.x.x.x` — это внутренняя кухня Docker, НЕ адрес в твоей сети.

## 4. Какой IP закрепить за ноутом A

Возьми адрес **в той же подсети**, что и роутер, но **вне диапазона раздачи DHCP**.
Например, если роутер `192.168.1.1` и раздаёт `192.168.1.50–192.168.1.200`, то для
ноута A подойдёт `192.168.1.10` (ниже диапазона). Диапазон DHCP виден в админке
роутера (раздел DHCP).

Самое надёжное — **DHCP reservation** (бронь по MAC): тогда конфликта с пулом не
будет в принципе, даже если адрес внутри диапазона.

---

## 5. Два способа сделать IP постоянным

### Способ A — DHCP reservation на роутере (рекомендую)
В админке Cudy: **DHCP → Address Reservation / Привязка адресов** → добавь MAC
ноута A (из раздела 3) и желаемый IP (`192.168.1.10`). Перезагрузи ноут или
переподключи Wi-Fi — он получит этот адрес. Плюс: настройка в одном месте, ничего
не ломается, если ноут переедет на другой Wi-Fi той же сети.

### Способ B — статический IP в самом Windows (запасной)
Если в роутере брони нет/непонятно. PowerShell **от администратора** на ноуте A
(подставь свои числа: IP вне DHCP-пула, шлюз = роутер):
```powershell
# узнать индекс адаптера:
Get-NetIPConfiguration | Where-Object { $_.IPv4DefaultGateway } | Select InterfaceIndex, InterfaceAlias
# назначить статику (пример для индекса 12):
New-NetIPAddress -InterfaceIndex 12 -IPAddress 192.168.1.10 -PrefixLength 24 -DefaultGateway 192.168.1.1
```
> ⚠️ Адрес ОБЯЗАТЕЛЬНО вне диапазона DHCP, иначе роутер выдаст его кому-то ещё → конфликт.
> Откатить к авто: `Set-NetIPInterface -InterfaceIndex 12 -Dhcp Enabled`.

> ⚠️ Если ноут A подключён по Wi-Fi, а бронь/статику сделал на Ethernet (или
> наоборот) — адрес не применится. Закрепляй IP того адаптера, через который он
> реально подключён (`InterfaceAlias` из раздела 3).

---

## 6. Ноут B и устройства игроков

- **Ноут B** — можно оставить на DHCP (постоянный IP ему не нужен, к нему никто не
  обращается напрямую). Главное, чтобы он был в той же подсети — это произойдёт
  само, раз он подключён к тому же роутеру.
- **Телефоны/планшеты игроков** — просто подключаются к Wi-Fi, получают IP
  автоматически, открывают `http://bank.lan` (или `http://<IP_ноута_A>`). Ничего настраивать не надо.

---

## 7. Быстрая проверка адресации

```powershell
# на ноуте B — видит ли он ноут A:
ping 192.168.1.10
# на ноуте B — открыт ли нужный порт на ноуте A:
Test-NetConnection 192.168.1.10 -Port 80
```
`ping` отвечает и `TcpTestSucceeded : True` → адресация и порты в порядке.
