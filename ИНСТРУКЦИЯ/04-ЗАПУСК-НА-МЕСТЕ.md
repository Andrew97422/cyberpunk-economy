# 🚀 04 — Запуск на месте (без интернета)

К этому моменту должно быть готово:
- ✅ Образы собраны дома и загружены на ОБА ноута ([01](01-ДОМА-С-ИНТЕРНЕТОМ.md), [03](03-ПЕРЕНОС-ОБРАЗОВ.md)).
- ✅ Папка проекта скопирована на ноут B.
- ✅ Сеть настроена, ноут A с постоянным IP ([02](02-СЕТЬ-И-РОУТЕРЫ.md), [02A](02A-КАК-УЗНАТЬ-IP.md)).

Запускать **без `-Build`** — образы уже готовы, интернет не нужен.

> Выбрана конфигурация **Primary + Standby** (ради отказоустойчивости, см.
> [08](08-ОТКАЗОУСТОЙЧИВОСТЬ.md)). Ниже — основной путь. Сплит-вариант оставлен
> в конце как альтернатива.

> Если IP ноута A отличается от `192.168.1.10` — подставь свой во все команды.

## Вариант 1 (основной): весь стек на ноуте A, ноут B — резерв

### Шаг 1. Ноут A — поднять всё одной командой

Самое простое — **двойной клик по `СТАРТ.cmd`** в папке проекта. Он сам проверит
Docker (запустит, если выключен), поднимет весь стек, дождётся готовности и
проверит логин. То же из PowerShell:
```powershell
cd "D:\Лагерь июнь 2026"
.\deploy\balancer\start-all.ps1
```
Или «вручную», если нужно:
```powershell
docker compose -p game-camp -f docker-compose.yaml up -d
```
Это поднимает весь стек: один Postgres (со всеми БД), Kafka, шлюз, фронтенд и все
сервисы (включая `analytics`). В all-in-one сервисы общаются через внутренний
`kafka:9094`, поэтому `CORE_HOST` настраивать НЕ нужно.

> Образы уже переименованы в `game-camp-*`, поэтому пересборки не будет —
> запуск идёт из готовых образов (интернет не нужен).

Дождись, пока контейнеры станут здоровыми:
```powershell
docker compose -p game-camp ps
```

### Шаг 2. Ноут B — НИЧЕГО не запускаем (горячий резерв)
В норме ноут B простаивает. Но он должен быть готов подхватить:
- на нём уже есть все образы и папка проекта;
- настрой приём бэкапов и потренируй failover — всё в [08](08-ОТКАЗОУСТОЙЧИВОСТЬ.md).

### Шаг 3. Настроить авто-бэкап на ноуте A
Чтобы при гибели A не потерять данные — включи бэкап по расписанию с копией на B
(см. [08, Уровень 2](08-ОТКАЗОУСТОЙЧИВОСТЬ.md)):
```powershell
.\deploy\balancer\backup.ps1 -PeerShare \\192.168.1.11\Backups   # разовая проверка
```

### Шаг 4. Проверить, что всё работает
С любого устройства в сети:
```
http://bank.lan          (или http://192.168.1.10)
```
Вход в админку: `admin` / `admin12345`. Сквозная проверка с ноута A:
```powershell
.\deploy\balancer\healthcheck.ps1 -EntryIp 192.168.1.10 -PeerIp 192.168.1.11
```

> Если ноут A умрёт — поднимаешь весь стек на ноуте B и восстанавливаешь бэкап.
> Пошагово: [08 — Failover](08-ОТКАЗОУСТОЙЧИВОСТЬ.md).

## Вариант 2 (альтернатива): сплит по двум ноутам

Если решишь делить нагрузку (ценой двух точек отказа и отсутствия аналитики),
вместо Варианта 1 запусти балансировщик. **Ноут A первым:**
```powershell
# ноут A:  .\deploy\balancer\balance.ps1 -Entry -PeerRamGB 8  -CoreHost 192.168.1.10
# ноут B:  .\deploy\balancer\balance.ps1        -PeerRamGB 16 -CoreHost 192.168.1.10
```
Здесь `CORE_HOST` обязателен на ОБОИХ (иначе ноут B не найдёт Kafka).
Подробности и аварийный план — [08, Вариант 2](08-ОТКАЗОУСТОЙЧИВОСТЬ.md).

## Полезные команды

| Действие | Команда (из папки проекта) |
|---|---|
| Статус контейнеров | `docker compose -p game-camp ps` |
| Логи (живые) | `docker compose -p game-camp logs -f` |
| Логи одного сервиса | `docker compose -p game-camp logs -f core` |
| Остановить (данные целы) | `docker compose -p game-camp down` |
| Бэкап вручную | `.\deploy\balancer\backup.ps1 -PeerShare \\192.168.1.11\Backups` |
| Проверка здоровья | `.\deploy\balancer\healthcheck.ps1 -EntryIp 192.168.1.10` |
| **Обнулить данные** (только админ) | `.\deploy\balancer\reset-data.ps1 -Yes` ⚠️ необратимо |

> ⚠️ НИКОГДА не добавляй `-v` к `down` — сотрёшь все данные игры!

## Порядок выключения / включения

- **Выключение:** `docker compose -p game-camp down` (БЕЗ `-v`).
- **Включение:** `docker compose -p game-camp -f docker-compose.yaml up -d`.
- Контейнеры с `restart: unless-stopped` — после перезагрузки ноута и старта
  Docker Desktop поднимутся сами.

Проблемы → [05 — Если что-то сломалось](05-ЕСЛИ-ЧТО-ТО-СЛОМАЛОСЬ.md).
Отказоустойчивость → [08](08-ОТКАЗОУСТОЙЧИВОСТЬ.md).
