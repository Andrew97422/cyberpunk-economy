# 🔌 07 — Эксплуатация: питание, сон, обновления, данные

Ноутбуки будут работать как **серверы** несколько дней подряд. По умолчанию ноут
засыпает, гасит сеть и сам ставит обновления — для сервера это смерть. Настрой это
ЗАРАНЕЕ (дома) на ОБОИХ ноутах.

---

## 1. Запретить сон и «ничего не делать» при закрытии крышки

Иначе при простое или закрытой крышке ноут уснёт и сервер пропадёт из сети.

PowerShell **от администратора** (на обоих ноутах):
```powershell
# не уходить в сон / гибернацию / не гасить экран при питании от сети:
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 0

# при закрытии крышки (от сети) — НИЧЕГО не делать:
powercfg /setacvalueindex SCHEME_CURRENT 4f971e89-eebd-4455-a8de-9e59040e7347 5ca83367-6e45-459f-a27b-476b1d01c936 0
powercfg /setactive SCHEME_CURRENT
```
> На батарее (`-dc`) поведение можно оставить обычным — главное, чтобы при работе
> от сети ноут не засыпал. Держи ноуты **включёнными в розетку**.

Проверка текущих настроек:
```powershell
powercfg /query SCHEME_CURRENT SUB_SLEEP
```

## 2. Не дать Windows перезагрузиться ради обновления

Авто-перезагрузка посреди мероприятия уронит всё. На обоих ноутах:
- **Параметры → Центр обновления Windows → Приостановить обновления** на максимум
  (1–5 недель) — на время мероприятия.
- Там же **«Период активности»** (Active Hours) — выставь на всё время работы лагеря.
- Не нажимай «Обновить и перезагрузить» вручную, пока идёт мероприятие.

## 3. Электропитание помещения

- Оба ноута — **в розетку**. Аккумулятор = «бесплатный ИБП» на случай моргания
  света, но не вечный.
- Если возможны отключения света — после восстановления Docker Desktop должен
  стартовать сам (см. п. 5), и контейнеры поднимутся автоматически.

## 4. Антивирус и брандмауэр

- При первом запуске Windows может спросить разрешение для Docker/портов — **разреши**.
- Сторонний антивирус может блокировать порты или тормозить Docker — на время
  мероприятия добавь Docker в исключения (или поставь на паузу защиту сети).

## 5. Автозапуск Docker и контейнеров

- Docker Desktop → Settings → General → включи **«Start Docker Desktop when you
  sign in»** на обоих ноутах.
- Также включи автологин Windows ИЛИ просто не выходи из учётки, чтобы после
  перезагрузки рабочий стол загрузился и Docker стартовал.
- Контейнеры запущены с `restart: unless-stopped` — после старта Docker они
  поднимутся сами. Отдельно запускать `СТАРТ.cmd` / `start-all.ps1` после каждой
  перезагрузки не обязательно (но можно — хуже не будет).

## 6. Данные игры — НЕ потеряй

- Данные (балансы, аккаунты и т.д.) лежат в **именованных томах Docker** и
  сохраняются между перезагрузками и `docker compose down`.
- ⚠️ **НИКОГДА не добавляй `-v` к `down`** (`docker compose down -v`) — это сотрёт
  все тома и обнулит игру. Для остановки используй просто:
  ```powershell
  docker compose -p game-camp down
  ```

### (Опц.) Резервная копия данных
Перед важным днём можно забэкапить том БД (пример для основной БД на ноуте A):
```powershell
docker run --rm -v game-camp_postgres_data:/data -v ${PWD}:/backup alpine `
  tar czf /backup/core-db-backup.tar.gz -C /data .
```
Имена томов смотри: `docker volume ls`.

## 7. Ежедневный ритм

- **Утро:** включить ноут A (если выключали) → дождаться Docker → потом ноут B.
  Проверить `http://bank.lan` (или `http://<IP_ноута_A>`).
- **Вечер:** можно оставить работать; если выключаешь — на каждом
  `docker compose -p game-camp down` (БЕЗ `-v`!).

## 8. Помни про единую точку отказа

Kafka, шлюз и фронтенд — только на ноуте A. **Если ноут A выключится/уснёт —
встанет вся система** (ноут B сам по себе бесполезен). Поэтому за ноутом A следи
особенно: питание, сон, обновления, стабильное подключение к роутеру (лучше кабель).
