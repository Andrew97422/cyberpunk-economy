# 🆘 05 — Если что-то сломалось

Типовые сбои и как лечить. Ищи свой симптом.

---

## Docker пытается СОБИРАТЬ образ на месте (и падает без интернета)

**Причина:** имя образа не совпало с тем, что ждёт compose — он решил, что образа
нет, и полез собирать.

**Проверка:** `docker images "game-camp-*"` — образы вообще есть?
- Нет → перенос не довёз образы. Повтори [03 — Перенос образов](03-ПЕРЕНОС-ОБРАЗОВ.md).
- Есть, но имена другие → собирали дома НЕ под проектом `game-camp`. Дома пересобери
  командой из [01, шаг 3](01-ДОМА-С-ИНТЕРНЕТОМ.md) (с `-p game-camp`) и перенеси заново.

**Главное:** запускай строго БЕЗ `-Build`. Если в команде есть `-Build` — убери.

---

## Сервисы на ноуте B не находят Kafka / в логах таймауты

**Причина:** неправильный `CORE_HOST`.

**Лечение:**
1. На ОБОИХ ноутах в `.env` строка `CORE_HOST` должна = IP ноута A (напр.
   `CORE_HOST=192.168.1.10`). Проверь оба файла.
2. IP ноута A не должен меняться — он должен быть закреплён на роутере
   ([02, шаг 2](02-СЕТЬ-И-РОУТЕРЫ.md)).
3. С ноута B проверь доступность порта Kafka:
   ```powershell
   Test-NetConnection 192.168.1.10 -Port 9092
   ```
   `TcpTestSucceeded : True` — связь есть. False → порт закрыт брандмауэром на
   ноуте A ([02, шаг 4](02-СЕТЬ-И-РОУТЕРЫ.md)) или неверный IP.

---

## Устройства не открывают `http://bank.lan` (или `http://192.168.1.10`)

1. С устройства пропингуй: `ping 192.168.1.10`. Нет ответа → проблема в сети/роутерах
   ([02](02-СЕТЬ-И-РОУТЕРЫ.md)), устройство в другой подсети, или ноут A по Wi-Fi отвалился.
2. Порт открыт? С ноута B: `Test-NetConnection 192.168.1.10 -Port 80`.
3. Имя `bank.lan` не открывается, а по IP работает? Значит, дело в DNS —
   см. [09 — Красивый адрес (DNS)](09-КРАСИВЫЙ-АДРЕС-DNS.md).
3. Контейнер фронтенда жив? На ноуте A: `docker compose -p game-camp ps` —
   строка `frontend` должна быть `running`.

---

## Контейнер постоянно перезапускается (OOM — нехватка памяти)

**Симптом:** в `docker compose -p game-camp ps` статус `Restarting`, в логах
`OOMKilled` или `exit 137`.

**Причина:** ноуту не хватает памяти, контейнер упёрся в `mem_limit`, ИЛИ Docker
выделено мало памяти (частое на 8 ГБ ноуте).

**Лечение:**
1. Проверь, сколько памяти у Docker: `docker info --format "{{.MemTotal}}"`
   (раздели на 1073741824 = ГБ). Ноуту B нужно ≥ 5 ГБ. Если мало — подними лимит
   через `.wslconfig` ([00, п.4](00-ЧТО-НУЖНО-ЗАРАНЕЕ.md)).
2. Закрой лишние программы на ноуте, освободи ОЗУ.
3. Запусти `balance.ps1` ещё раз — если свободной памяти стало меньше, план
   может измениться. Посмотри вывод: если пишет загрузку >100% — группами уже не
   разложить.
4. Тогда варианты: третий ноут, либо более мелкое дробление по отдельным сервисам
   (напиши мне — сделаем). Лимиты памяти лежат в `deploy/balancer/compose.*.limits.yaml`.

---

## Сервер был доступен, а потом «пропал» (ноут уснул)

**Причина:** ноут A ушёл в сон/гибернацию или закрыли крышку — Kafka/шлюз/фронтенд
исчезли из сети, вся система встала.

**Лечение:** разбуди ноут A. На будущее — отключи сон и реакцию на крышку
([07, п.1](07-ЭКСПЛУАТАЦИЯ-И-ПИТАНИЕ.md)) и держи его в розетке.

---

## Логин не проходит / токен «протух» сразу (разъехались часы)

**Причина:** в закрытой сети без интернета часы ноутов разошлись. JWT-токены
завязаны на время — при большой разнице авторизация ломается.

**Лечение:**
1. Сверь время на обоих ноутах (часы Windows).
2. Выстави одинаковое время вручную (Параметры → Время и язык → Дата и время →
   «Установить время вручную»). Достаточно совпадения в пределах минуты.
3. Если в сети есть устройство с точным временем — ориентируйся на него. Идеально —
   синхронизировать оба ноута перед выездом, пока есть интернет.

---

## После перезагрузки ноута сервисы не поднялись

Проверь, что **Docker Desktop запущен** (значок кита в трее, не серый).
Контейнеры стоят с `restart: unless-stopped` и поднимутся сами ПОСЛЕ старта Docker.
Если Docker не настроен на автозапуск: Docker Desktop → Settings → General →
«Start Docker Desktop when you sign in».

Если не поднялись — запусти `balance.ps1` заново (см. [04](04-ЗАПУСК-НА-МЕСТЕ.md)).

---

## Конфликт портов (`port is already allocated`)

Какой-то порт занят другим процессом или старым контейнером.
```powershell
docker compose -p game-camp down          # погасить старое
docker ps -a                               # нет ли чужих контейнеров на тех же портах
```
Используемые порты (Primary/all-in-one): **80** (фронтенд), **53** (DNS), **8080–8091**
(шлюз и сервисы), **9092** (Kafka), **5432** (БД).

---

## Скрипт `.ps1` не запускается («не удалось загрузить, политика выполнения»)

Windows блокирует запуск скриптов. Проще всего запускать через **`СТАРТ.cmd`**
(двойной клик) — он уже обходит политику. Если запускаешь `.ps1` напрямую — разово
разреши в ЭТОМ окне PowerShell:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
Затем снова запусти нужный скрипт.

---

## Заканчивается место на диске (Docker раздулся)

После многих пересборок виртуальный диск Docker растёт и не сжимается сам.
Запусти **от администратора** (он погасит стек, сожмёт диск и поднимет обратно;
данные не теряются):
```powershell
powershell -ExecutionPolicy Bypass -File "D:\Лагерь июнь 2026\deploy\balancer\compact-docker-disk.ps1"
```
Также можно очистить кэш сборки: `docker builder prune -a -f`.

---

## Кракозябры вместо русских букв в выводе скрипта

Это косметика, на работу не влияет. Если мешает — выполни перед запуском:
```powershell
chcp 65001 | Out-Null; $OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
```
