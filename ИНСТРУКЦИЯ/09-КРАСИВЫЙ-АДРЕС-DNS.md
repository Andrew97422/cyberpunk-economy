# 🌐 09 — Красивый адрес вместо IP (http://bank.lan)

Цель: участники открывают **`http://bank.lan`** (или `http://game.lan`), а не IP.
Порт уже убран — фронтенд на стандартном **80**, поэтому адрес чистый, без `:8088`.

**DNS уже встроен в стек** — поднимается вместе со всем остальным (сервис `dns`,
контейнер `game-dns`, образ dnsmasq). Он раздаёт имена `bank.lan` / `game.lan` →
IP ноута A. Тебе остаётся **один шаг**: указать роутеру выдавать этот ноут как DNS.

> Имена `.lan` выбраны намеренно: `.local` конфликтует с mDNS на части устройств.

---

## Как это работает (по-простому)

Устройство вводит `bank.lan` → спрашивает у **DNS-сервера** «какой IP?». В нашей
сети DNS-сервер — это контейнер `game-dns` на ноуте A, он отвечает `192.168.1.10`.
Чтобы устройства спрашивали именно его, роутер должен в DHCP выдавать адрес ноута A
как DNS.

---

## Что нужно сделать (всего 3 пункта)

### 1. Указать правильный IP ноута A
В файле `.env` строка `LAN_IP` должна равняться **реальному закреплённому IP**
ноута A (тому, что забронирован на роутере, напр. `192.168.1.10` — см.
[02A](02A-КАК-УЗНАТЬ-IP.md)):
```
LAN_IP=192.168.1.10
```
Если менял — перезапусти стек (`СТАРТ.cmd` или `start-all.ps1`), чтобы DNS подхватил.

### 2. Открыть порты в брандмауэре ноута A
PowerShell **от администратора**:
```powershell
New-NetFirewallRule -DisplayName "Camp HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
New-NetFirewallRule -DisplayName "Camp DNS UDP" -Direction Inbound -Protocol UDP -LocalPort 53 -Action Allow
New-NetFirewallRule -DisplayName "Camp DNS TCP" -Direction Inbound -Protocol TCP -LocalPort 53 -Action Allow
```

### 3. В DHCP роутера указать DNS-сервер = IP ноута A
В админке **главного роутера → DHCP → DNS-сервер** впиши `192.168.1.10`
(адрес ноута A). Сохрани.
- На **Cudy**: раздел LAN/DHCP, поле «Основной DNS» (Primary DNS).
- На **Keenetic**: «Домашняя сеть» → «Параметры IP» / DHCP → «Серверы DNS».

> Этот способ работает с **любым** роутером — даже если он не умеет собственные
> локальные имена. Имена отдаёт наш контейнер, а роутер лишь говорит устройствам,
> к кому обращаться за DNS.

---

## Устройства должны «перечитать» DNS

Клиенты получают DNS при подключении. Чтобы подхватили:
- переподключиться к Wi-Fi (забыть/подключить сеть заново) или перезагрузиться.

## Проверка

С любого устройства в сети (или с ноута A):
```powershell
nslookup bank.lan          # должен ответить 192.168.1.10
```
Затем открой в браузере `http://bank.lan` — откроется интерфейс.
Локально на ноуте A проверить DNS-контейнер можно так:
```powershell
Resolve-DnsName bank.lan -Server 127.0.0.1
```

---

## Запасной вариант: имена прямо на роутере (без нашего DNS)

Если не хочешь, чтобы DNS зависел от ноута A, и роутер умеет локальные записи
(**Keenetic умеет**), пропиши имя прямо в нём — тогда контейнер `dns` не нужен:

**Keenetic** (через командную консоль / SSH):
```
ip host bank.lan 192.168.1.10
ip host game.lan 192.168.1.10
system configuration save
```
Cudy в базовой прошивке локальные имена обычно **не умеет** — для него используй
встроенный DNS (основной способ выше).

> Можно оставить и то, и другое — конфликта нет, просто дублирование.

---

## Важные нюансы

- **IP всегда работает как запасной**: `http://192.168.1.10` откроет то же самое,
  если у кого-то DNS не подхватился.
- **DNS живёт на ноуте A.** Если ноут A падает и поднимается failover на ноут B —
  DNS поедет вместе со стеком (образ dnsmasq есть и на B). Но `LAN_IP`/адрес должен
  указывать на тот ноут, что реально обслуживает. Проще всего при failover отдать
  ноуту B адрес ноута A (см. [08](08-ОТКАЗОУСТОЙЧИВОСТЬ.md)).
- **Если на ноуте A уже работает свой DNS/служба на порту 53** — контейнер `dns`
  не поднимется (порт занят). Тогда используй запасной вариант (имена на роутере).
