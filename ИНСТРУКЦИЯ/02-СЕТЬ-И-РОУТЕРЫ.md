# 🌐 02 — Сеть и роутеры (на месте, без интернета)

Цель: одна локальная сеть с большим покрытием, в которой ноут A всегда доступен
по постоянному адресу, а устройства подключаются к любому из двух роутеров.

## Главные правила (нарушишь — сеть «глючит непонятно почему»)

1. **Одна подсеть, один DHCP.** Адреса раздаёт только ОДИН роутер (главный).
   На втором роутере DHCP **выключен**.
2. **У ноута A — постоянный IP.** Его адрес зашит в Kafka и в `.env`. Сменится —
   всё развалится.
3. Интернет не нужен: всё работает локально.

## Роли роутеров

- **Cudy AX3000 — ГЛАВНЫЙ** (быстрее, Wi-Fi 6). DHCP включён. Это «хозяин» сети.
- **Keenetic KN-1610 — расширитель покрытия.** DHCP выключен, режим «Точка
  доступа / Extender».

Роутеры разных марок → фирменный Mesh между ними не заработает. Варианты связи:
- **Кабель между роутерами + Keenetic в режиме «Точка доступа»** — лучший вариант:
  полная скорость, максимальная стабильность. Если есть хоть какая-то возможность
  протянуть один кабель — сделай так.
- **Без кабеля — WDS / режим повторителя на Keenetic.** Работает, но скорость на
  дальнем роутере падает примерно вдвое. Зафиксируй один канал Wi-Fi, одинаковые
  имя сети (SSID) и пароль на обоих — тогда устройства сами переключаются.

## Схема адресов (пример)

| Устройство | IP | Примечание |
|---|---|---|
| Cudy AX3000 (главный) | `192.168.1.1` | DHCP включён |
| Keenetic (расширитель) | `192.168.1.2` | DHCP выключен, статический IP |
| **Ноут A (входной)** | `192.168.1.10` | **закрепить** (DHCP reservation) |
| Ноут B | `192.168.1.11` | можно по DHCP |
| Устройства игроков | `192.168.1.50+` | по DHCP |

## Пошагово

### 1. Настроить главный роутер (Cudy)
- Включи, зайди в его веб-панель (адрес обычно на наклейке снизу).
- DHCP — **включён**.
- Задай имя сети (SSID) и пароль.

### 2. Закрепить IP за ноутом A (важно!)
В панели Cudy найди раздел **DHCP → Address Reservation / Привязка адресов** и
привяжи MAC-адрес ноута A к адресу `192.168.1.10`.

MAC ноута A посмотри так (PowerShell на ноуте A):
```powershell
Get-NetAdapter | Where-Object Status -eq "Up" | Select-Object Name, MacAddress, ifIndex
ipconfig
```
> Лучше подключи ноут A к главному роутеру **кабелем** — центральный узел по
> проводу работает несравнимо стабильнее, чем по Wi-Fi. Закрепляй IP именно того
> адаптера, через который он подключён.

### 3. Настроить второй роутер (Keenetic) как расширитель
- Переведи в режим **«Точка доступа»** (если соединяешь кабелем) или
  **«Усилитель/WDS»** (если без кабеля).
- DHCP — **выключить**.
- IP роутера — статический `192.168.1.2`.
- SSID и пароль — **такие же**, как на Cudy (для бесшовного перехода).

### 4. Открыть порты на ноуте A (брандмауэр Windows)
Только на ноуте A. Запусти PowerShell **от администратора**:
```powershell
New-NetFirewallRule -DisplayName "Camp HTTP"     -Direction Inbound -Protocol TCP -LocalPort 80   -Action Allow
New-NetFirewallRule -DisplayName "Camp DNS UDP"  -Direction Inbound -Protocol UDP -LocalPort 53   -Action Allow
New-NetFirewallRule -DisplayName "Camp DNS TCP"  -Direction Inbound -Protocol TCP -LocalPort 53   -Action Allow
# 9092/8080 — нужны только для сплит-варианта (для Primary+Standby не обязательны):
New-NetFirewallRule -DisplayName "Camp Kafka"    -Direction Inbound -Protocol TCP -LocalPort 9092 -Action Allow
New-NetFirewallRule -DisplayName "Camp Gateway"  -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```
> Ноуту B входящие правила НЕ нужны: его сервисы только сами стучатся на Kafka
> ноута A (исходящие соединения разрешены по умолчанию).

> **Для конфигурации Primary + Standby** (весь стек на A) реально нужен только
> порт **80** (фронтенд, новый адрес `http://bank.lan` без порта). Порты 9092/8080
> нужны только для сплит-варианта — держать их открытыми не вредно, но не обязательно.
> При **failover на ноут B** не забудь открыть 80 и на нём (или настрой правило на
> обоих заранее):
> ```powershell
> New-NetFirewallRule -DisplayName "Camp HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
> ```
> Красивое имя вместо IP — см. [09 — Красивый адрес (DNS)](09-КРАСИВЫЙ-АДРЕС-DNS.md).

### 5. Проверить связь
С ноута B пропингуй ноут A:
```powershell
ping 192.168.1.10
```
Идут ответы → сеть готова. Дальше → [04 — Запуск](04-ЗАПУСК-НА-МЕСТЕ.md).

> Если ping не проходит, но оба в сети — на ноуте A временно проверь, не режёт ли
> ICMP брандмауэр; для диагностики можно разрешить:
> `New-NetFirewallRule -DisplayName "Allow Ping" -Protocol ICMPv4 -IcmpType 8 -Direction Inbound -Action Allow`
