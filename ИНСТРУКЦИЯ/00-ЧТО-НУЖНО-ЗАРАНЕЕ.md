# 🧰 00 — Что нужно проверить ДО всего (предусловия)

Прежде чем собирать и настраивать — убедись, что «железо» и система готовы.
Эти проверки делаются дома, при интернете. Если что-то не так — на месте уже не починить.

---

## 1. Железо и роли

- **Ноут A** (16 ГБ) — входной/сильный. Здесь сборка, Kafka, шлюз, фронтенд.
  Желательно с Ethernet-портом (чтобы подключить к роутеру кабелем).
- **Ноут B** (8 ГБ) — рабочий. На нём только Docker Desktop.
- **Два роутера**: Cudy AX3000 (главный) + Keenetic KN-1610 (расширитель).
- **Кабель Ethernet** (хотя бы один — для ноута A к роутеру; очень желательно).

## 2. Место на диске

Docker и образы съедают много. Проверь свободное место:
```powershell
Get-PSDrive C | Select-Object Used, Free
```
- **Ноут A:** нужно **≥ 25 ГБ** свободно (сборка + кэш + образы + том БД).
- **Ноут B:** нужно **≥ 15 ГБ** свободно (загрузка образов + тома БД).

Если мало — почисти или собирай/храни на диске `D:`.

## 3. Docker Desktop работает (значит, виртуализация уже в порядке)

Docker Desktop требует включённой виртуализации (VT-x/AMD-V в BIOS) и компонентов
Windows (WSL2). **Простая проверка:** если Docker Desktop запускается без ошибок и
команды ниже отвечают — всё уже настроено, ничего трогать не надо.
```powershell
docker version
docker run --rm hello-world   # дома, при интернете: должно вывести "Hello from Docker!"
```
Если Docker не стартует и пишет про виртуализацию — включи в BIOS
«Intel VT-x / AMD-V» и компоненты Windows «Платформа виртуальной машины» и
«Подсистема Windows для Linux», перезагрузись. (На ноуте B Docker уже стоит — значит,
там это есть.)

## 4. Сколько памяти отдано Docker (ВАЖНО для ноута B, 8 ГБ)

Docker на Windows работает в виртуалке (WSL2) и по умолчанию может забрать НЕ всю
память. На 8 ГБ ноуте сервисам может не хватить, хотя «по железу» памяти достаточно.

**Проверить, сколько Docker реально видит:**
```powershell
docker info --format "Памяти у Docker: {{.MemTotal}} байт"
```
Раздели на 1073741824 — получишь гигабайты. Ноуту B нужно, чтобы у Docker было
**≥ 5 ГБ** (группа finance ест ~2.3 ГБ + запас).

**Если мало — поднять лимит (WSL2-бэкенд):** создай/отредактируй файл
`C:\Users\<твоё_имя>\.wslconfig`:
```ini
[wsl2]
memory=5GB
processors=4
```
(на ноуте A можно `memory=10GB`). Затем применить:
```powershell
wsl --shutdown
```
и перезапустить Docker Desktop.

> Если в Docker Desktop выбран **Hyper-V backend** (а не WSL2): память меняется
> ползунком в Settings → Resources → Memory, файл `.wslconfig` не нужен.

## 5. Питание (критично — ноут будет работать как сервер!)

См. отдельный файл [07 — Эксплуатация и питание](07-ЭКСПЛУАТАЦИЯ-И-ПИТАНИЕ.md):
ноут-сервер НЕ должен засыпать и перезагружаться сам. Настрой это заранее.

## 6. (Опционально) Node.js — для прогона тестовых сценариев

Если хочешь прогонять `e2e/run-scenarios.mjs` для проверки — поставь Node.js на
ноут A дома. Не обязательно для работы, только для диагностики.
