# Балансировщик: авто-распределение сервисов по двум ноутам

> ⚠️ Это документация **альтернативного** режима (сплит по двум ноутам).
> Основной режим проекта — **Primary+Standby** (весь стек на одном ноуте через
> `СТАРТ.cmd`), он описан в папке `ИНСТРУКЦИЯ/`. В этой же папке `deploy/balancer/`
> лежат и скрипты основного режима:
> - `start-all.ps1` — запустить весь стек; `reset-data.ps1` — обнулить данные;
> - `backup.ps1` / `restore.ps1` — бэкап/восстановление; `healthcheck.ps1` — проверка;
> - `export-images.ps1` / `import-images.ps1` — перенос образов на ноут B;
> - `compact-docker-disk.ps1` — сжать раздувшийся диск Docker (от админа).
>
> Ниже — только про `balance.ps1` (сплит).

Скрипт сам определяет ОЗУ машины и раскладывает группы сервисов так, чтобы
минимизировать пиковую загрузку памяти каждого ноута. Группа **core**
(Kafka + шлюз + фронтенд) всегда на «входной» ноде — машине с флагом `-Entry`,
к которой подключаются устройства.

## Группы сервисов

| Группа    | Сервисы                                            | Резерв памяти |
|-----------|----------------------------------------------------|---------------|
| `core`    | kafka, gateway(core), frontend, core-postgres      | ~2.0 ГБ       |
| `finance` | banking, account, access (+ 3 БД)                  | ~2.3 ГБ       |
| `rest`    | card, terminal, marketplace, news, audit (+ 5 БД)  | ~3.8 ГБ       |

Резервы заданы через `mem_limit` в `compose.*.limits.yaml` — это страховка от
перегруза: контейнер не возьмёт больше лимита.

## Как запускать

Один раз узнай объём ОЗУ обоих ноутов. Затем на КАЖДОМ ноуте:

```powershell
# На СИЛЬНОМ ноуте (он же входной; пример: сам 16 ГБ, сосед 8 ГБ):
.\deploy\balancer\balance.ps1 -Entry -PeerRamGB 8 -CoreHost 192.168.1.10

# На СЛАБОМ ноуте (пример: сам 8 ГБ, сосед 16 ГБ):
.\deploy\balancer\balance.ps1 -PeerRamGB 16
```

- `-Entry` ставится ТОЛЬКО на одном (более сильном) ноуте.
- `-PeerRamGB` — ОЗУ ВТОРОГО ноута (своё определяется само).
- `-CoreHost` — LAN-IP входного ноута; обновит `CORE_HOST` в `.env`. Этот же
  IP закрепи на роутере за входным ноутом (DHCP reservation), иначе при смене
  адреса Kafka перестанет находиться.
- `-DryRun` — показать план, ничего не запуская.
- `-Build` — пересобрать образы (НУЖЕН интернет; в закрытой сети не используй).

## Важно: закрытая сеть

`-Build` тянет зависимости из интернета и упадёт в офлайне. Собери образы заранее
дома (`docker compose ... build` или `balance.ps1 ... -Build`), а на месте
запускай без `-Build` — Docker возьмёт готовое из кэша.

## Проверка и остановка

```powershell
docker compose -p game-camp ps        # статус контейнеров этой машины
docker compose -p game-camp logs -f   # логи
docker compose -p game-camp down       # остановить
```

## Если памяти впритык

Если скрипт пишет, что лучший вариант превышает безопасный лимит (>100%),
группами уже не разложить — нужна третья машина или дробление на отдельные
сервисы (мельче гранулярность). Текущая раскладка — на уровне трёх групп,
потому что так не требуется менять исходные compose-файлы.
